Global vs local

What stays standard, what each market owns.

A first draft of the framework the role asks for. The line will move once I see the data, but there has to be a line.

GGlobal standard

Set once, the same everywhere.

  • Lifecycle stagesSign-up, first lesson, habit, subscriber, at risk, lapsed.
  • Journey logicTriggers, goals, exit rules and holdouts per programme.
  • KPIsActivation, retention, LTV, payback. One definition, one dashboard.
  • GuardrailsConsent, suppression, frequency caps, deliverability.
  • Brand voiceThe core message and what we never say.

LLocal by market

Decided per market, inside the guardrails.

  • Channel mixEmail-first, push-first or messaging-app-first.
  • TimingSend windows, local holidays, school and work calendars.
  • OffersPrice points, payment methods, promo moments.
  • ToneFormality, emoji, how direct a reminder can be.
  • ContentLocalised and culturally checked, not just translated.

First 90 days

Audit, fix, then expand.

Written from the outside, so the order will change once I'm inside.

DAYS 1–30

Know the base

  • Audit every live journey in Iterable: goal, audience, results, holdout.
  • Deliverability health check by domain, IP and market.
  • Map consent, suppression and list hygiene across markets.
  • Agree one KPI tree and a market-by-channel WBR view with the Head of Consumer Marketing.

DAYS 31–60

Fix the core

  • Rebuild the highest-impact journeys first: first lesson, trial-to-paid, renewal.
  • Set experimentation standards and a shared test log.
  • Write the global vs local framework and the first playbooks.
  • Pick the first messaging-app pilot market and provider.

DAYS 61–90

Expand

  • Launch the WhatsApp pilot with a holdout and a go/no-go date.
  • Ship the first AI workflows: localisation and WBR reporting.
  • Plan WeChat and KakaoTalk evaluations.
  • CRM roadmap for the next two quarters.

Each programme gets a goal, a holdout and a date to decide whether to keep it.

AI & automation

Less manual work, more markets.

Four workflows I'd build early. Each one has a person checking the output before it reaches a learner.

01

Localisation with a native check

AI drafts each market's version from the master message and a per-market style guide. A native speaker reviews before anything ships.

in master copy + style guides
out localised variants to review

02

WBR on autopilot

CRM results by market and channel pulled, compared and summarised every week, with the three things worth discussing on top.

in Iterable + BI data
out WBR section, draft

03

Deliverability watch

Daily check on bounces, complaints and reputation by domain and market, with an alert before a problem becomes a block.

in ESP + postmaster data
out alert + suggested fix

04

Test ideas from results

Past experiments and journey data summarised into the next hypotheses to test, ranked by likely impact.

in test log + journey metrics
out ranked test backlog

The goal isn't more messages. It's the same small team covering more markets without the quality dropping.
